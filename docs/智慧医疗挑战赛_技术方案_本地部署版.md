## 一、重要澄清：人形立牌 ≠ 锥桶

比赛中有**两种完全不同的物体**，不要搞混：

| 物体 | 外观 | 位置 | 作用 | 处理方式 |
|---|---|---|---|---|
| **锥桶（障碍物）** | 蓝白色三角锥 | A/C 区随机摆放 | 不能碰，碰了罚时 10s | **LiDAR 避障**即可，完全不需要视觉 |
| **人形立牌** | 人形图案立牌（A5尺寸） | C 区固定位置 | 必须识别 + 大模型图生文描述 | **相机拍照 → 端侧 VLM 图生文 → 语音/屏幕输出** |

⚠️ **大模型/VLM 不是拿来识别锥桶的**，是用来完成**人形立牌图生文**这个比赛硬性子任务的。锥桶用雷达避障就够了。

## 五、端侧 VLM 部署方案（RDK X5 8G）

### 5.1 可选模型

| 模型 | 大小 | 量化方式 | RDK X5 适配性 | 首Token延迟 | 参考来源 |
|---|---|---|---|---|---|
| **Gemma-3-4B-IT-QAT** | ~4B | QAT 4bit | ⭐⭐⭐⭐⭐ 官方验证 | 1.5~3s | HUAT-IAE-OriginCar_X5 方案 |
| **Qwen2-VL-2B-Instruct** | ~2B | INT4/INT8 | ⭐⭐⭐⭐⭐ 轻量 | 1~2s | 阿里云官方 |
| **Qwen2-VL-7B-Instruct** | ~7B | INT4 | ⭐⭐⭐⭐ 8G内存刚好 | 2~4s | 需 swap 或量化更激进 |
| **MiniCPM-V-2.6** | ~2.8B | INT4 | ⭐⭐⭐⭐ 社区验证 | 1~2s | 面壁智能 |

**推荐首选**：Gemma-3-4B-IT-QAT（QAT = Quantization Aware Training，量化感知训练，精度损失最小）。参考湖北汽车工业学院方案已验证在 RDK X5 上可运行。

### 5.2 部署要点

1. **模型预热**：VLM 首次加载需 3~5s 初始化。比赛时应在发车前**预加载模型到内存**，触发时直接推理，避免冷启动延迟。
2. **输入分辨率**：降低图像分辨率到 336×336 或 224×224，可大幅加速推理（牺牲少量精度，不影响"人形立牌"这种简单场景）。
3. **提示词模板**：固定提示词减少 token 数，加速生成：
   ```
   "描述图中人物的姿势、动作和特征。"
   ```
4. **异步处理**：到达 VLM 语义航点 → 停车 → 触发 VLM 推理（异步）→ 同时准备语音播报 → 拿到结果立即输出 → 继续行驶。推理期间不需要完全等待，可以边推理边做其他初始化。

### 5.3 超时兜底

端侧 VLM 推理可能遇到内存不足或偶发延迟。必须设置**8秒超时**机制：
- 超时未返回 → 跳过图生文，继续执行后续任务（避免卡死导致整体失败）
- 输出兜底文案："检测到人物立牌"

## 七、IMU 标定详解（非建图，纯离线测量）

### 7.1 为什么需要标定？

IMU 出厂有**零偏（bias）**——即使静止不动，陀螺仪也会输出非零角速度。这个零偏如果不扣除，EKF 融合后的航向会**持续缓慢旋转**，导致轨迹漂移。

**标定 = 测量并扣除这个零偏。和建图没有任何关系。**

### 7.2 静态零偏标定（赛前做）

```python
# 伪代码 - 在RDK上运行，车模静止放置
import numpy as np

# 订阅 /imu/data，采集1000帧（约10秒，100Hz IMU）
gyro_x_list, gyro_y_list, gyro_z_list = [], [], []
for i in range(1000):
    msg = get_imu_msg()  # 阻塞接收
    gyro_x_list.append(msg.angular_velocity.x)
    gyro_y_list.append(msg.angular_velocity.y)
    gyro_z_list.append(msg.angular_velocity.z)

# 计算零偏
gyro_bias_x = np.mean(gyro_x_list)
gyro_bias_y = np.mean(gyro_y_list)
gyro_bias_z = np.mean(gyro_z_list)

print(f"Gyro Bias: x={gyro_bias_x:.6f}, y={gyro_bias_y:.6f}, z={gyro_bias_z:.6f}")
# 输出示例：Gyro Bias: x=0.002341, y=-0.001123, z=0.015678

# 保存到配置文件
calibration = {
    "gyro_bias_x": gyro_bias_x,
    "gyro_bias_y": gyro_bias_y,
    "gyro_bias_z": gyro_bias_z,
}
```

使用时：
```python
calibrated_gz = raw_gz - gyro_bias_z  # 减去零偏后再送入EKF
```

## 八、竞赛策略与速度规划

### 8.1 各阶段速度建议

| 阶段 | 路径长度 | 建议速度 | 预计用时 | 说明 |
|---|---|---|---|---|
| A区：P→任务点 | ~2.5m | 0.30 m/s | ~8s | 开阔地带，可以快 |
| 任务点停车+扫码 | — | 0 m/s | ~5s | 必须停稳识别 |
| B区：通道通过 | ~1.5m | 0.20 m/s | ~8s | 通道窄，稳妥 |
| C区：环形巡航 | ~6m | 0.15 m/s | ~40s | 最窄最危险，降速保零失误 |
| C区：人形立牌检测+VLM | — | 0 m/s | ~8s | 触发式处理，VLM预热后推理 |
| 返回：C→B→P | ~4m | 0.25 m/s | ~16s | 可适当提速 |
| **总计** | **~14m** | — | **~85s** | 含安全余量 |

实际完赛时间取决于避障绕行次数和子任务处理效率。合理目标是 **≤90s** 稳定完赛，速度提升后有望压缩到 **60s 以内**。

### 8.2 避障策略（零碰撞优先）

```
优先级1：Nav2 DWB 局部规划绕行（首选，路径平滑）
  ↓ 失败/障碍物太近
优先级2：VFH 反应式避障（紧急，直接输出cmd_vel）
  ↓ 仍然太近
优先级3：停车等待2秒，再尝试绕行
  ↓ 仍然卡住
优先级4：申请重启（发车手手动放回P点，计时继续）
```

**关键参数**：
- `inflation_radius`: 0.25m（锥桶半径约0.1m，留足安全边距）
- `costmap_resolution`: 0.05m（精度足够，计算量可控）
- `max_vel_x`: 0.30 m/s（A区），0.15 m/s（C区）——**按区域动态切换**

### 8.3 重启策略

比赛允许**无限次重启**，但每次重启发车手需要向裁判申请、放回P点、重新发车。**计时不停**。

**什么时候应该重启？**
- ✅ 冲出场地（肯定回不来了）
- ✅ 严重偏离航点（>0.5m），纯惯导无法自行回归
- ✅ 连续卡死超过5秒
- ❌ 只是轻微偏离（<0.2m），尝试自行修正
- ❌ 只是速度变慢，还能继续

**重启决策时间**：从发现问题到申请重启，控制在 **3秒内**。

### 8.4 二维码与人形立牌处理策略

| 子任务 | 策略 | 容错 |
|---|---|---|
| 二维码识别 | 车到任务点后**完全停稳**（速度<0.01m/s），保持2秒，连续拍摄3帧，取最可靠的一帧 | 若3帧都失败，原地旋转±15°再试 |
| 人形立牌 | C区环形巡航时**持续运行YOLO检测**，检测到人形立牌后**停车**，相机对准拍摄，触发端侧VLM | VLM推理设置8秒超时，超时则输出兜底文案继续行驶 |
| 图生文展示 | 屏幕显示 + 语音播报同时进行（最保险） | 任一方式成功即算完成 |

## 十一、总结

方案核心：**用代码写死航点 + EKF融合定位 + LiDAR只避障不定位 + 端侧VLM做人形立牌图生文**。

这个方案可行的前提是：
1. ✅ 航点预设精度够（赛前用尺子量场地）
2. ✅ IMU标定做好（零偏+里程计米/脉冲+转向角映射）
3. ✅ C区速度压住（0.15m/s，宁慢勿错）
4. ✅ 零碰撞（宁可绕远也不碰锥桶）
5. ✅ 端侧VLM预热+超时兜底（避免推理卡死）
6. ✅ 重启决策快（3秒内判断，不犹豫）

**最可能翻车的点**：纯惯导在C区环形漂移导致压线。建议C区航点密度加密到每0.3m一个点，并设置更小的跟踪容差（0.08m）。
